# @acosmi/dsh-llm-acosmi

English | [中文](README.zh.md)

Private DSH-GUI provider plugin backed by the pinned `@acosmi/sdk-ts` managed-model API. The `acosmi` route exists only after the account snapshot is ready and a current catalog response confirms at least one selectable chat model. A newer account state aborts the pending confirmation and invalidates its generation, so a late catalog result cannot reactivate a withdrawn route. Catalog entries that are locked, disabled, non-chat, or covered by an uncertain entitlement response are never selectable.

Each SDK client carries a local-authorization lifetime signal, and the adapter separately owns the ready-route lifetime. Logout, secure-storage failure, account-route withdrawal, or plugin disposal aborts admitted provider streams before removing the route; those streams fail with the stable `AUTH` code. Each request binds model-catalog validation and stream dispatch to the same SDK client and route signals, so a late catalog from an old account cannot be dispatched through a replacement client. A later authorization receives fresh signals and cannot revive an earlier stream.

The managed-model catalog's `maxTokens` value describes output capability; it is not a request default. The plugin requires an independent positive `config.maxTokens`, which Harness materializes into omitted conversation requests before logging and dispatch. The desktop bundle sets 8,192 tokens. An explicit per-request value remains authoritative. The required `config.streamIdleTimeoutMs` controls provider-stream silence; the desktop bundle sets 120 seconds.

`WINDOW_LIMIT_EXCEEDED` becomes the stable non-default-retryable Harness code `WINDOW_LIMIT`, distinct from exhausted account quota and ordinary transient 429 rate limiting. Its user-facing message states that the rolling-window reservation rejected the request: the current server response reports used and limit values but omits the incoming and projected values that caused the decision, so those two reported values alone do not prove exhaustion.

Duplicate final provider tool names become the stable non-default-retryable code `TOOL_NAME_COLLISION`. This classification preserves the logged Harness tool catalog and exposes the provider defect without silently removing a model-visible tool. The Nexus owner reported the client-name precedence repair deployed on 2026-08-15; the defensive mapping remains in place, while final DSH compatibility evidence still requires the managed DeepSeek, Kimi, and Qwen matrix from the repaired deployment.

The adapter translates the Harness message and streaming vocabularies without adding prompt text. Acosmi access and refresh tokens remain in the Host secret provider; only provider-neutral chunks and a versioned, minimal replay record reach the session log. Replay parsing accepts only the supported exact block fields, bounded JSON tool input, and the durable assistant source's provider and model; unknown fields or mismatched sources fail before a later model request. Consecutive Anthropic user messages are canonicalized into one provider turn, so parallel Harness tool results remain together when sent to compatibility endpoints. This rule is selected by the catalog format and therefore applies equally to managed DeepSeek and Kimi routes that select Anthropic. Tool-result payloads are text-only; image, reasoning, nested tool, and extension blocks fail instead of being silently discarded. When an end-user field is required, the provider receives a fixed-length SHA-256 digest instead of the local Harness session id. Image input is intentionally rejected until a durable attachment conversion is implemented.

An assistant response reuses its complete provider replay only for the same managed model, only while that replay exactly matches the durable visible projection, and only when every Anthropic thinking block carries a non-empty signature. After a model switch, an exactly matched replay is converted to portable history: provider-signed reasoning and provider-only blocks are omitted, while visible text and Harness tool calls remain. A same-ID catalog format change follows the same rule: Anthropic signed state never becomes OpenAI `reasoning_content`, and unsigned OpenAI reasoning never becomes Anthropic exact replay. Anthropic-format portable blocks retain canonical `acosmi_ephemeral: true` markers for the SDK sanitizer; OpenAI-format history removes those temporary blocks and linked tool results before flattening them into native messages. A reasoning-only response contributes no empty assistant message. Missing, mismatched, or modified replay still fails closed instead of sending an invalid signature or reasoning transcript to the target model.

Managed `server_tool_use` and `web_search_tool_result` blocks are provider-only history, not Harness tool calls. The adapter keeps those blocks, text citations, and canonical `acosmi_ephemeral: true` markers in validated replay while exposing only the resulting assistant content to Harness. The account service configures the SDK to strip the ephemeral blocks and linked results before the next managed-model request.

Raw SDK stream events are handled by an explicit vocabulary. Both `error` and `failed` carry provider failures; `started`, validated empty or non-empty `sources`, and settlement events are non-model-visible control metadata. A successful stream requires exactly one non-empty finish reason followed only by settlement controls and `message_stop`. Malformed sources, unknown event types, empty tool identities, a missing, duplicate, or unsupported stop reason, model content after that reason, or a nominally successful response with no Harness-visible block fail closed instead of being silently ignored or recorded as a successful answer.

The installed SDK `2.17.0` still rewrites filtered and unknown OpenAI stream finish reasons to a normal `end_turn` before this adapter receives them. An empty filtered response reaches the adapter's `EMPTY_RESPONSE` defense, but partial content cannot reveal whether the provider filtered the remainder. The release ledger therefore keeps `acosmi-sdk-openai-finish-reason-preservation` blocked until a published SDK preserves those reasons losslessly; this adapter does not infer them from model text or duplicate the SDK's HTTP/SSE implementation.

A keyless assembled snapshot boots the real Loader, ACP transport, agent loop, Acosmi adapter, and JSONL persistence over a deterministic account boundary. The boundary rejects the request unless `max_tokens` is 8,192, every Harness tool name is unique, and exactly one client `web_search` exists. The durable fixture pins the 1,000,000-token model context plus provider-only managed-search blocks, their canonical ephemeral markers, an exact citation, usage, and the visible assistant projection.

SDK and provider error text is used only to select a stable Harness failure code. Serialized failures and renderer messages use fixed client-safe copy while retaining non-sensitive HTTP status and retry timing, so response bodies, account fields, tokens, and endpoints do not cross through `LlmError.message`.

The pinned Acosmi SDK owns HTTP request retries. The adapter therefore publishes a Harness retry policy with zero additional attempts, preventing the two layers from multiplying one model call.
