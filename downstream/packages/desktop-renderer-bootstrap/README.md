# @acosmi/dsh-desktop-renderer-bootstrap

English | [中文](README.zh.md)

Builds the immutable production client allowlist, copies exact client bundles into the packaged renderer, and starts the upstream `AppWebEntry` over official `__DSH_TRANSPORT__` hooks. The graph retains each `dsh.client.external` request and orders its dynamic supplier before the consumer. The allowlist carries `dsh-client-ui-renderer` as a dynamic client plugin, plus the web-app attachment and `@` reference plugins so Vision intake and composer references occupy the same slots as the Host roster. A client entry may name a shell-static package dependency only when the upstream `PLATFORM_MODULES` baseline supplies it, while the static web shell owns boot and hands off its mount point after the graph activates. The desktop graph omits `ui-brand-official`; product marks come from the overlay brand seats.

Renderer HTML loads a content-addressed, same-origin module-loader facade, then the modules and runtime classic bundles as blocking parser preloads, and only then the Vite module entry. The build rejects a missing or reordered preload and any inline script, preserving `script-src 'self'`. The version 2 asset manifest records the full SHA-256 of every final Vite output byte, including the facade; the custom protocol verifies the selected file again before serving it, while renderer boot accepts only the exact credential-free `app://dsh-gui/plugins/` URL and canonical revision query. Production never scans local plugins or downloads JavaScript.
