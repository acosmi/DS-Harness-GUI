# @acosmi/dsh-desktop-release

English | [中文](README.zh.md)

Owns the six machine-readable DSH-GUI release ledgers and their closed JSON schemas. `pnpm run desktop:verify` validates every ledger, the canonical stable/canary identity assignments and fixed installer GUIDs, the exact required responsibility, external-input, platform, native-module, and per-module target rosters, each external input's release-blocking policy and owning role, stable blockers, ABI records, and the recorded lockfile hash without treating code completion as release readiness. It also requires every direct Acosmi SDK consumer to match the audited version, verifies that version and integrity against the lockfile registry entry, and rejects a stale local OAuth patch once the published package is state-capable.

The identity ledger records the public macOS Developer ID metadata and the exact SHA-1 selector used by stable packaging. The post-sign gate also discovers every Mach-O file in the application and requires each one to carry that Developer ID team, authority chain, and secure timestamp; the outer application additionally has to match the channel Bundle ID and hardened runtime. The ledger deliberately excludes local certificate and CSR paths, keychain locations, private keys, P12 files, passwords, and notarization credentials. The `apple-signing-and-notary` input remains blocked after local identity validation because notarization and final signed, notarized, stapled arm64 and x64 artifact evidence are separate requirements.

`pnpm --filter @acosmi/dsh-desktop-release run verify:signed` and every main-process build marked for stable signing fail closed if the published Acosmi SDK lacks OAuth state protection, TokenStore failure propagation, an authenticated account subject, or lossless OpenAI stream finish reasons; they also fail if any release-blocking external input remains blocked, the product commit is not frozen, compatibility evidence is incomplete, the publisher legal entity is absent, or a responsibility lacks its owner, distinct backup, evidence, or due date. The development gate without a trusted publisher signature reports those blockers but does not authorize signing, publishing, or release promotion.
